## 重跑

```bash
npm ci
npm test
npm run eval:model
node scripts/check-ui.mjs
```

`eval:model` 会使用 `.env` 的模型配置并消耗额度，总请求上限 10 次包含修复及合并；不会调用转写服务。报告保存为 `artifacts/model-evaluation.json`。每次运行重新计数，不能未经授权重复执行付费验证。

UI 检查要求本机安装 Chrome 和开发依赖，并先生成上述模型报告；后端注入模拟响应，不会再调用模型。可用环境里没有 Chrome 时不要把无法运行包装成通过。截图和导出写入被 Git 忽略的 `artifacts/`。

CI 只安装依赖并执行无付费的自动化测试。本地已执行同样的安装/测试步骤，但新 GitHub Actions 运行结果需推送后确认。

## 尚未验证与已知边界

- 没有本轮真实 YouTube/Supadata 转写、线上 Vercel 或真实 OpenAI 调用；合成字幕检查只覆盖摘要与时间定位，不代表 YouTube 获取成功率。
- 传统 DOC 仅有注入解析器的单元路径测试，未添加真实二进制 DOC 样本；真实文件测试覆盖 PDF 和 DOCX。
- Schema 与引文匹配不证明结论语义正确；摘要遗漏和错误归纳仍可能存在。
- 云端长转写、长正文可能超出时间预算；浏览器 PDF 解析耗时不计入服务端摘要 trace。
- 实验性视觉 OCR 未进行真实模型测试；本地直连下载/视觉识别未覆盖完整取消链，不作为稳定主路径。
- 实例内限流不能代替生产鉴权与分布式配额；公开部署仍需监控额度、防刷和隐私告知。
- 无大规模负载、对抗注入、安全审计、RAG、自动订阅或历史持久化，不以这些能力对外宣传。

面试版本可围绕“多源解析 → 受控摘要 → 原文核查 → 导出”演示，先冻结功能范围；不能把这次检查当作生产 SLA。
